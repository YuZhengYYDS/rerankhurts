# Controlled simulation pilot contract — frozen before model execution

Purpose: build and execute a controlled, synthetic evidence-retrieval environment. Never label simulator output as human judgments, genuine medical advice, or independent real-world external replication. Keep legacy E0/E3 runs and the human E2 gate unchanged.

Data directory: experiments/simulation/data/pilot_v1/
Files: corpus.jsonl, questions.jsonl (system-visible); oracle.jsonl and specification.json (evaluator-only). All generated content is fictional. Model input is question text and document text only, with no fact IDs, chunk-kind labels or oracle fields rendered.

60 independent fictional cohort worlds (10 per six stress scenarios), each with one information need presented as open and source-constrained versions = 120 tasks. Split whole worlds: 20 development, 40 test, fixed deterministically before any scores. Keep a balanced distribution across scenarios. Alternate lexical rendering families between development and test; no shared entities or documents across worlds. This is a pilot, not independent human sampling or proof of real-world transfer.

Scenario names: aligned, distributed, alternative_source, stale_version, near_match, late_evidence. Mix partial and full support, redundant chunks on one URL, current/obsolete version text, close but different cohort distractors, and supporting facts placed late in a chunk. Do not force a winning configuration or tune after reading test outcomes. Realism is limited to specified document/workflow structures, not validated clinical behavior.

Corpus record: {chunk_id, url, text}. Include version/source information in the actual text when necessary to interpret it. Use fictional *.invalid domains, multiple source families, opaque IDs without kind/fact labels. Each cohort must have full valid support in the corpus for all necessary facts, also from the allowed source for constrained tasks. Document text carries no machine-readable fact IDs.

Question record: {qid, question, group_id, topic, gold_urls, construction_source:"synthetic_information_need", split:"dev"|"test", policy:"open"|"constrained", scenario}. Gold URL is the designated page and is not necessarily sufficient or the only supporting page. Metadata is NOT input to models. Open/constrained questions differ by an explicit source rule, not retrospectively imposed gold-URL identity.

Oracle record per qid: {qid, group_id, split, policy, scenario, required_fact_ids:[str], allowed_url_prefixes:[str], claims:[{chunk_id,fact_id,start_char,end_char,status:"valid"|"contradictory"|"obsolete",admissible:bool}]}. Every claim span is an exact substring of corpus text and includes the subject/context, value and version needed for a complete fact. Multiple spans can support a fact. Counterclaims must explicitly contradict a required fact (not just concern a different subject); near-match distractors are not claims for this question. Required facts and intended content precede document rendering. Oracle files must stay separate from corpus/questions.

Evaluation uses the pinned budget tokenizer's offset mapping: count a claim only if its complete span survives in the ACTUALLY delivered token prefix for its chunk. Never infer support from URL, chunk membership alone, latent model knowledge, or a partial proposition. Compute full fact coverage U_sim, coverage fraction, contradiction/obsolete exposure and C_sim separately. U_sim=all required facts have delivered valid support; conflicting/obsolete text is separately reported, not silently erased or called clinical sufficiency. For constrained tasks also report source-admissible full fact coverage and C_sim=nonempty context AND every delivered chunk URL allowed by the predefined source policy. No generated answer or A score is claimed.

Reuse the existing 20 configurations and frozen model/tokenizer SHAs. Real dense retrieval and cross-encoder scores are required; do not fabricate ranks. Preserve per-stage candidate IDs and token streams. Record synthetic scope in a separate simulation backend; leave the original run_factorial.py and historical trace identities unchanged.

Selection: primary open-evidence 512-token endpoint, equal-weight information needs. Select among the 10 configurations at that budget on 20 dev groups by G_final versus U_sim. Ties use ascending reranker flag (none first), pool, cap order off/pre/post, config_id — a deterministic structural rule, not measured cost. Freeze before model run. Evaluate delta=mean(U_sim of dev-selected U config)-mean(U_sim of dev-selected G config) on 40 test groups. Report both choices, all ties, paired group bootstrap 95% interval (5000 draws, seed 20260928), and selection frequencies under development bootstrap. Secondary 2048-budget contrast is exploratory. Constrained-task scores are descriptive; no source-feasible selector claimed in this pilot. A null or reversed gap must be retained.

Input/code/model hashes, generation seed=20260928, complete status, scenario counts, all stage scores and loss stages are included in artifacts. No result-dependent regeneration or model/configuration tuning. Smoke runs test correctness only and use separate output directories. Synthetic data code gets unit tests of generation separation/coverage, truncated facts, alternate support, duplicates, obsolete/contradictory context, and rejection by human-only E2.
