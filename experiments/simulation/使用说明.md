# 受控仿真环境：运行与结果

这个环境模拟信息检索中的任务需求、来源限制、文档更新、相似内容干扰和上下文预算。第一版使用虚构的肿瘤登记行政工作流：每个任务需要找齐路由、复核时间和放行条件三项事实。它的真实性范围是这些信息处理结构；临床判断、真实患者行为和真人效用尚未验证。

## 数据怎样产生

1. 先固定 60 个虚构任务世界的事实、需求和开发/测试划分。
2. 将事实写入不同来源的文档，同时加入部分支持、替代来源、过时版本、明确反例、相似对象和位置较后的证据。共生成 780 个片段。
3. 每个世界产生开放来源、限定来源两个任务，共 120 个任务；同一世界始终留在同一组。
4. 现有 BGE 检索器和 m3 重排器真实运行 20 种配置，产生 2,400 条完整轨迹。
5. 独立评分程序检查实际交付的 token：只有完整事实句进入上下文才计为覆盖。事实答案和评分标签不会输入检索、重排模型。

`U_sim` 表示必要事实是否全部覆盖。矛盾信息、过时信息和来源违规另外报告。所有标签均标为 `synthetic_oracle`，原来的人评分析入口仍会拒绝它们。

## 已执行的 pilot

使用 20 个世界开发选型、40 个世界独立测试，版本为 `pilot_v2`。主比较的上下文预算是 512 tokens；2,048 tokens 为探索性补充。

开发集上，10 个配置的完整事实覆盖率全部并列为 60%。按事先固定的并列规则，事实覆盖指标选择无重排配置，页面命中指标选择 m3 配置；后者同样属于开发集事实覆盖率的最优集合。

测试集上，两者的完整事实覆盖率分别为 22/40（55%）和 27/40（67.5%）。前者减后者为 -12.5 个百分点，条件配对 bootstrap 95% 区间为 [-25, 0] 个百分点。这次结果不支持“页面命中指标导致选错配置”，也不能说明两个指标等效。2,048-token 补充比较的差值为 -2.5 个百分点，区间为 [-7.5, 0]。

部分长证据任务在 512-token 下结构上不可能覆盖全部事实，因此测试集覆盖率上界至多为 85%。报告保留这些任务及原分母，没有为提高结果删题。

## 从仓库根目录运行

```powershell
pixi install --locked -e gpu
pixi run --locked sim-generate
pixi run --locked -e gpu sim-run
pixi run --locked -e gpu sim-evaluate
pixi run --locked python scripts/plot_simulation.py
```

`sim-generate` 只允许重建完全相同的已冻结数据；`sim-run` 支持相同命令断点续跑。如果只重算已有结果，执行 `sim-evaluate` 即可，它只需下载缺失的固定版本 tokenizer，不需要重新跑大模型。

主要文件：

- `data/pilot_v2/`：文档、问题、独立事实评分信息及冻结规范。
- `../runs/simulation_pilot_v2/`：真实模型运行记录与逐阶段轨迹。
- `results/pilot_v2/`：逐条分数、汇总、选型结果、预算可行性及图。
- `../../validation/simulation_audit.json`：独立程序的结果核算。
- `AMENDMENTS.md`：试运行发现的反例语义错误及版本修正记录。

73 项自动测试通过，全部 2,400 条记录已验证；完整运行和断点续跑均已执行。详细定义、已知局限和来源见同目录 README.md。
